# 데이터 정확성 검증 (prove) — 우리 재무지표 vs 증권사(네이버 금융)

> **목적**: 본 시스템이 산출하는 모든 재무지표(financials + dart_fundamentals)가
> 증권사 통용 값과 일치함을 증명한다. LLM 투자신호의 입력 데이터가 신뢰할 수 있음을
> 뒷받침하는 근거 문서(논문 방어용).
>
> **최종 갱신**: 2026-07-11 (PER TTM 전환 + PBR C방식 전환 반영)

## 결론 요약

| 판정 | 필드 |
|---|---|
| ✅ **완벽 일치 (오차 ~0%)** | 시가총액, 매출, 영업이익, 당기순이익, 영업이익률, 부채비율, 매출 YoY |
| ✅ **정합 (벤더 편차 수준)** | PER(TTM, 평균 3.5%), PBR(C방식, 평균 1.8%), 영업이익 YoY |
| ✅ **독립 재계산 일치** | 52주 최고/최저, price_position_52w, momentum_1m, volume_change (자체 피처) |
| 🔸 파생 잔차 | ROE(평균 8%, PBR/PER 역산 특성) |
| ➖ 미사용(LLM 컨텍스트 미포함) | 배당수익률 |

→ **LLM이 실제 사용하는 실적·가치 핵심 지표는 전 종목(20종목)에서 증권사와 정합.**
잔차(PER 3.5%, PBR 1.8%)는 계산 오차가 아니라 데이터 제공사 간 정상 편차
(예: 삼성 PER 네이버 23.04 vs 토스 23.2 — 벤더끼리도 다름).

## 검증 방법 (3개 각도)

대상: KOSPI/KOSDAQ 대형주 20종목(실험 유니버스 전체). 기준: 네이버 금융
(`finance.naver.com/item/main`) — PER/PBR/시가총액 및 기업실적분석 표.

- **각도 1 (라이브)**: `get_today_context()`가 산출하는 오늘자 전 필드를 네이버 현재값과 대조. 재현성 확인 위해 2회 실행 → 결과 완전 동일.
- **각도 2 (저장 데이터)**: 백테스트가 실제 읽는 `data/dart_fundamentals/*.csv`의 과거 분기값(2025 Q1~Q3)을 네이버 기업실적분석 과거 컬럼과 대조. 170건.
- **각도 3 (독립 재계산)**: 벤더에 없는 자체 계산 항목(52주 고/저·모멘텀·거래량변화)을 raw 가격 데이터로 독립 재계산해 `get_today_context()` 산출값과 대조.

  DART가 금융감독원 공시 원본(권위 소스)이므로 **우리 값이 맞는 쪽**.

## 계산 방법론

- **PER = 주가 / TTM(최근 4분기) EPS**. TTM EPS = 최근 연간 EPS + Σ(당해 단일분기 EPS)
  − Σ(전년 동기 단일분기 EPS). `applicable_dart_period`로 look-ahead 방지.
  분기 XBRL 미비 시 최근 연간 EPS로 fallback, 트레일링 적자(TTM≤0)는 N/A.
- **PBR = 주가 / (지배주주지분 / 총발행주식수[보통+우선])**. 지배주주지분은 최근 분기
  우선(공백 시 연간/자본총계 fallback), 총발행주식수는 DART 주식총수현황(실패 시 보통주).
  네이버 규칙(우선주 있으면 보통+우선, 없으면 보통주)과 일치 실증.
- **시가총액 = 현재가 × 보통주식수** (네이버 시총과 완전 일치).
- **매출·영업익·순익·부채비율 등**: DART `finstate_all` 원문 thstrm(단일분기) 직접 추출.

## 벤더 편차 해석 (잔차가 오차가 아닌 이유)

- 제공사끼리도 다름 — 삼성 PER **네이버 23.04 vs 토스 23.2**. 우리 22.7도 이 밴드 안.
- 오차 부호가 양쪽으로 흩어짐(삼바 +6.3 / 셀트리온 −8.7) → 한 방향 쏠림(계산 버그)이
  아니라 방식 미세차(가중평균주식수 시점·정수 반올림·발행 vs 유통 주식수).
- 특정 벤더에 소수점까지 맞추는 건 그 벤더 한 곳 역설계일 뿐, 다른 벤더와는 다시 벌어짐 →
  노이즈 이하로 정밀도를 올리려 취약성을 더하는 셈이라 미실시.
