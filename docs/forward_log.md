### ⚠️ 알려진 이슈: Claude Haiku의 cond1(무컨텍스트) 거절

**증상**: 삼성SDI·LG화학·HYBE·알테오젠 4종목의 cond1(종목명+현재가만 제공)에서 `call_llm`이 JSON 파싱 실패로 3회 재시도 후 실패. 원인은 API 오류가 아니라 **Claude가 "판단할 데이터가 부족하다"는 산문 거절 응답**을 반환한 것 (JSON 형식을 안 지킴).

**해석**: cond1은 원래 "컨텍스트 없음" 베이스라인으로 설계된 조건 — 정보 부족이 의도된 설정인데, Claude Haiku가 다른 모델(Gemini/GPT)과 달리 이 조건에서 20% 확률(4/20)로 형식을 어기며 거절함. 모델별 행동 차이로 판단, 코드 버그 아님.

**처리**: 재시도 없이 결측 처리 (사용자 결정). forward_eval 집계 시 해당 4건은 자연히 신호 없음으로 반영됨.

**향후 참고**: 매주 반복 시 Claude cond1에서 유사 거절이 재현되는지 관찰 필요. 반복적으로 발생하면 프롬프트 레벨 대응(예: "정보가 부족해도 반드시 JSON으로 최선의 추정 응답" 문구 추가) 검토 여지 있으나, 현재는 **동결된 프롬프트를 건드리지 않기로** 결정.

## 2026-07-29 (앱 개선 · forward 표본 위생)

정기 실행일 아님, 신호 생성 없음. app.py 개선 중 발견한 표본 오염 이슈와 조치 기록.

### 발견: 정식 배치가 아닌 신호 1건이 평가 표본에 포함됨

- **대상**: `results/forward/2026-07-11/gemini-2.5-flash-lite/005930_cond4.json` (삼성전자, 현재가 285,000, Buy 75%)
- **성격**: 07-11은 토요일로 주간 리듬(일요일)에서 벗어나며, 해당 폴더에 이 파일 **하나뿐**(정식 배치는 4모델 합산 약 396건). 현재가 285,000이 TODO C-0의 TTM PER 검증 예시와 일치해, 그날 TTM 전환 작업 중 단발 실행으로 생긴 것으로 판단.
- **영향**: `forward_eval.py`가 `results/forward/*/*/*.json`을 통째로 훑어 정식 신호와 구분 없이 `evaluation.csv`에 1행으로 집계됨. 1,585건 중 1건이라 수치 영향은 미미하나, 특정 종목·시점만 추가 표집되는 편향이며 "07-11에 왜 삼성전자 하나뿐인가"를 설명해야 하는 부담이 있음.

**조치**: 해당 폴더 제거. 원본은 커밋 `b436031`(5차 실험 결과)에 남아 복구 가능. `evaluation.csv`는 다음 `forward_eval.py` 실행 시 재생성되며 해당 행이 자동으로 빠진다.

### 재발 방지: 앱 시연 신호를 `results/forward_demo/`로 격리

app.py 분석 버튼은 `run_forward`를 그대로 호출하므로 시연 중 클릭할 때마다 같은 방식으로 정식 경로에 신호가 쌓인다. 리허설에서 한 종목을 여러 번 누르면 그 종목만 과대표집된다.

- **방식**: 신규 생성 신호를 `results/forward_demo/{날짜}/{model}/`로 이동. `FORWARD_DIR`의 **형제 폴더**라 `forward_eval.py`의 glob 범위 밖 → 평가 표본에서 자동 제외되고 `forward_eval.py` 수정도 불필요(코드 동결 유지).
- **주간 배치 보호**: 클릭 시점에 정식 경로에 파일이 이미 있으면(일요일 배치 직후 시연 등) 이동하지 않고 그대로 읽는다. 신규 생성분만 격리 대상.
- **시연 캐시**: `forward_demo/`의 당일 신호는 앱이 직접 읽어 재호출하지 않는다. 같은 종목을 반복 클릭해도 LLM 호출 0.
- **타임아웃 보정**: 3분 타임아웃 후 백그라운드 워커가 뒤늦게 정식 경로에 쓰는 경우에 대비해 그 경로를 회수 목록에 등록하고 다음 클릭 때 이동시킨다.

### 관찰 — cond1에서 Sell은 그대로, Buy만 사라진다

flash-lite cond1을 백테스트(2023-2025, 모델 cutoff 이전 가능)와 forward(2026-07~08,
cutoff 이후)에서 대조했다.

| 신호 | 백테스트 (720건) | forward (80건) |
|------|----------------|---------------|
| Buy | 한화에어로 14 · 알테오젠 4 · 기아 2 · 두산 2 | HD현대중공업 1 · 두산 1 |
| Sell | 에코프로비엠 33 · HYBE 21 · 카카오 17 · 크래프톤 17 · LG화학 1 · HD현대 1 | 에코프로비엠 4 · HYBE 4 · 카카오 2 · 크래프톤 2 · LG화학 1 |

- **Sell 상위 4종목이 순서까지 일치한다.** 3년 전 구간과 지금 구간에서 같은 종목을 같은
  순서로 팔라고 한다 → 시점 무관한 **종목 평판 prior**로 해석

## 남은 실행: 평가 2회 (신호 생성은 종료)

**신호 생성 주간 반복은 08-02로 종료됐다.** 남은 것은 평가뿐이다.

### 왜 매주가 아니라 2회인가 (2026-08-09 계획 변경)

`forward_eval.py`는 **상태를 누적하지 않는다.** 매 실행마다 `results/forward/*/*/*.json`을
전량 스캔해 주가로 처음부터 다시 계산하고 `evaluation.csv`를 통째로 덮어쓴다. 주가 캐시도
`get_price`가 마지막 날짜 이후 구간을 자동으로 따라잡는다(utils.py `if last_date < today`).
중간 수집이 필요한 단계는 08-02로 이미 끝났다.

따라서 **마지막에 한 번 돌린 결과는 매주 4번 돌린 결과와 동일하다.** 매주 실행은 데이터상
불필요하다. 그럼에도 2회를 남기는 이유는 아래 스모크 테스트 하나뿐이다.

| 실행일 | 목적 | 성숙 |
|-------|------|------|
| **2026-08-11 (화) 장 마감 후** | 스모크 테스트 | 07-12 배치 (1 / 4) |
| **2026-09-01 (화) 전후** | 최종 수치 확정 | 4 / 4 |

```bash
python src/experiment/forward_eval.py
```

**08-11 실행은 수치가 아니라 코드 경로 확인이 목적이다.** 지금까지 성숙 신호가 0건이라
`status="matured"` 분기와 `_summarize`의 적중률 집계는 한 번도 실행된 적이 없다. 특히
`hit_20d`가 object dtype이라 `astype(bool)`로 캐스팅하는 부분은 성숙분이 있어야 밟힌다.
9월 1일 마감 직전에 여기서 처음 터지면 곤란하므로 미리 한 번 통과시켜 둔다.

> 날짜는 근사다. `forward_eval.py`가 거래일을 세어 판정하므로 아직이면 `pending`으로 남는다.
> 09-01에 08-02 배치가 pending이면 며칠 뒤 다시 돌리면 된다. 여러 번 돌려도 무해하다.

### 거래일 계산 (2026-08-09 실측)

기존에 적어둔 "08-10 전후"는 **제헌절(07-17, 금) 휴장을 빠뜨린 계산이었다.** 실제 KRX
거래일로 세면 하루씩 밀린다.

- 진입은 신호일 다음 첫 거래일 종가다. 배치가 일요일 생성이므로 **월요일 종가가 진입가**이고
  금요일 종가가 아니다(LLM이 본 가격은 금요일 종가가 맞다. look-ahead 방지 규약).
- `calc_return`은 `iloc[0]`부터 `iloc[20]`까지 **총 21개 바**를 요구한다.
- 07-12 배치는 08-07까지 19개만 쌓였다(07-17 휴장으로 1개 부족). 21개 충족은 08-11이다.

| 배치 | 진입 | 성숙 예정 |
|------|------|----------|
| 07-12 | 07-13 | **2026-08-11 (화)** |
| 07-19 | 07-20 | 08-17 (월) |
| 07-26 | 07-27 | 08-24 (월) |
| 08-02 | 08-03 | 08-31 (월) |

> 2~4차는 추정이다. 광복절 08-15가 토요일이라 **대체공휴일이 08-17(월)에 적용되면 하루씩
> 더 밀린다.** KRX 2026 휴장일 캘린더로 확정하지 않았다. 최종 실행을 09-01로 잡은 것은
> 이 불확실성을 흡수하기 위해서다.

### 기타

- 신규 신호 생성 없음. **API 비용 0.** 이미 생성된 4배치의 20거래일 성과만 채운다
- 각 실행 후 이 문서에 결과를 한 줄씩 추가하고, 최종 실행 뒤
  [experiments_log.md](experiments_log.md) "백테스트 vs forward 대조" Part B의

  국면 한 주짜리라 어차피 다시 써야 하므로, 조기 집필의 실익이 없다는 판단이다

  않으므로 무관하다
